# Blackbox Plugin

私有源码仓库：[zemekeznb/blackbox-plugin](https://github.com/zemekeznb/blackbox-plugin)。

**Agent 执行黑匣子：留下执行过程中可观测的错误返回，以及在明确边界内再次出现的相同调用，供人回看、排查和分享。**

Agent 最后说「完成了」，并不代表中间没有失败。Blackbox Plugin 希望保留那些容易被最终回复省略的过程：任务最终成功，前面的错误仍然存在；任务中断，也不必等 Agent 写总结才留下记录。

当前产品是 **Codex + Windows + 本地插件 + 本地网页**，原名 TAS Notes。它是可运行、覆盖有限的工程原型，还没有完成持续真实使用的价值验证。2026-10-08 已将本机插件、桌面入口与服务更新至 0.3.5，完成项目展开会话、真实会话名、选择记忆、异常卡片与独立详情，并验证实际浏览器下载。此前 0.3.2 完成 `InputTooLarge` 边界修复及限定的桌面真实采集、关联、停用验收。独立 CLI 的沙箱启动故障按用户要求暂缓调查。实际部署与证据见 [当前进展](docs/current-status.md)、[最新界面验收](docs/reports/NOTES-029-session-navigation.md) 和 [桌面采集验收报告](docs/reports/NOTES-022-desktop-acceptance.md)。

## 为什么做这个项目

最初的设想是减少团队成员重复调查同一问题：某人的 Agent 已经尝试过几种办法，另一个人却只能重新排查或等待对方整理。当前将切入点收紧为：**先让用户看见 Agent 执行过程中值得留下的错误，不要求维护另一套人工总结流程。**

希望验证的价值包括：过程可见、失败经验可回看、减少翻找长对话、便于导出给同事或其他 Agent。接收者无需安装本插件。目标用户、节省时间和付费意愿仍是产品假设；测试通过不能证明这些假设成立。

它不局限于软件 Bug。文件处理、Blender 操作等任务也可能产生有用的工具错误，但适用场景不等于接入覆盖。画面不好看、规划不合理、幻觉和语义上的任务失败，不由本插件自动判断。

## 怎么使用

1. 通过 Codex 正常流程安装插件、信任 Hook，并为明确选择的项目启用记录。安装不等于所有项目自动开启。
2. 照常执行任务。宿主 Hook 负责投递事件，不需要每次提醒 Agent 写记录。
3. 从 Blackbox Plugin 桌面入口，或通过 CLI/技能打开本地页面。已有服务可复用；没有可用服务时按需启动。
4. 选择项目和项目内会话，按工具、记录时间筛选异常；查看操作、错误正文和已有再次调用，必要时展开技术详情。
5. 按需下载 Markdown 快照。无需人工编辑、确认或额外模型调用。

Codex 关闭后，仍可查看已经保存的记录。服务不随系统自动启动；再次打开入口可重新启动。不要把临时端口和 token 链接当作永久书签。

默认页面为异常卡片，点击进入独立详情；返回及浏览器后退保留当前页面会话的筛选、已加载记录和滚动位置。完整操作、返回和已有再次调用位于详情，来源与摘要收进默认折叠的“技术详情”，可下载当前快照。采集范围、隐私和运行信息收在“采集与隐私”。2026-10-08 已正常更新至 `0.3.5+codex.2026100802`，最新验收见 [NOTES-029](docs/reports/NOTES-029-session-navigation.md)。整页重载或关闭后重开只恢复所选会话，不恢复之前的列表状态。

默认按“项目 → 会话 → 异常记录”浏览，桌面左侧展开项目、选择会话，窄屏分层进入。导航仅显示有已保存事件的项目与会话；停用但仍有记录的项目可以回看，采集状态放在帮助中。会话使用本机 Codex 的真实名称，读取失败时显示“未命名会话”和日期，编号收进技术详情。只读名称查询不读取回合正文、不恢复会话、不调用模型，也不扫描宿主聊天文件。

上次选中的会话保存在本机，服务重启或换端口仍可恢复；首次使用选择最近有记录的会话。当前页面内最多保留最近 10 个会话的筛选、已加载卡片、快照和滚动位置，整页重载仅恢复会话选择，不恢复旧列表。未归属到已启用项目的会话仍不采集。记录时间提供全部、今天、近七天（含今天）与自定义范围；仅自定义显示起止，按浏览器本地日期筛选本机保存时间，不把它当作精确错误发生时间。

异常页不再提供旧历史导航；兼容 `/history` 页面仍支持会话、Agent 总结和人工版本的**只读查看，人工版本可逐版本导出**。新建总结、人工编辑、保存审阅版本的入口已经移除。默认不自动清理。2026-10-08 根据用户明确授权，旧 Anything 试验数据已从本机活动库清除，当前 Blackbox 试用、备份和迁移归档保留，见 [NOTES-025 清理报告](docs/reports/NOTES-025-legacy-cleanup.md)。

## 当前能够记录什么

| 层次 | 当前能力 |
| --- | --- |
| 保存来源 | 已启用项目的可见输入、工具调用与返回、最终回复及生命周期事件；比异常列表更广 |
| 列出观察 | 从已保存的 `Bash` 返回中识别完整 Python traceback 或指定 PowerShell 诊断格式 |
| 附上再次调用 | 同一会话和已捕获回合边界内，相同工具、完整输入完全一致的再次调用及其返回 |

**首页没显示，不等于没有采集。** 当前仍保存比异常列表更广的授权事件；NOTES-017 的长期存储收缩尚未实施，也没有自动清理历史。

### 错误识别与证据等级

Python 检测不再仅列举四个异常名称，而是检查 traceback 标头、栈帧和异常尾行。允许前面有普通日志，也能识别 `TypeError`、`ModuleNotFoundError` 等符合格式的异常。长输出保留首尾片段；只有一个片段内存在完整格式时才命中，不能跨截断缺口拼接证据。

| 证据来源 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 历史真实 Codex CLI 0.160.1 Hook 样本 | 捕获过 `FileNotFoundError`、`JSONDecodeError`、`TimeoutExpired`、`PermissionError`，以及指定 PowerShell 程序启动错误格式 | 不代表所有桌面工具、宿主版本、MCP 或拒绝路径已覆盖 |
| 本轮本机 Python 子进程样本与回归 | 更广的 traceback 格式、前置日志、首尾截断等解析行为经过检查 | 不是新一轮真实 Codex Hook 覆盖证据 |
| NOTES-022 / 当前 Codex 桌面真实执行 | 5 次合成命令实际执行并落盘，4 条异常；同回合重复保留并关联、跨回合停止；停用/恢复生效，页面及实际下载一致 | 不证明自然任务价值、全部工具覆盖或 Agent 自主修复；静默非零退出仍漏记 |
| NOTES-022 / 独立 CLI 0.162.0-alpha.2 | 先前生命周期事件落盘、停用后不追加；正常安装信任状态通过 | 只读沙箱工具启动仍被 setup refresh / node_repl 文件占用阻断，不能把桌面通过写成 CLI 故障已修复 |
| 页面上的格式命中 | 某次返回里确实保存了匹配的诊断文字 | 不证明是本次执行产生的故障；打印旧日志也可能命中 |

历史宿主证据见 [采集覆盖报告](docs/reports/NOTES-013-capture-coverage.md)。其中一次相同调用的后续成功返回由测试驱动准备条件，不能当作已捕获 Agent 自主修复的证明。

以下边界仍存在：

- 无正文、仅非零退出的命令失败：本轮真实桌面 `exit 7` 返回为空且没有检测命中，仍会漏记。
- stdout/stderr 合并后若其他文字插入 traceback 内部、破坏完整格式，可能漏记；本轮保留了这种真实样本，没有放宽规则来掩盖它。
- 宿主参数校验拒绝、宿主 deadline、审批拒绝、通用 MCP 错误：实际送达契约仍未验证。
- 保存 `exit_code`、`status`、`isError` 等字段时仅保留其值，不自动解释成经验证的失败信号。
- 改命令、改参数、跨会话或未送达的操作，不会自动补进记录。
- 普通文字里有 `error`、空输出、重复调用、搜索无匹配，不直接认定为 Bug。

未来是否支持更多工具、超时或内部失败，应由实际可见契约和误报评估决定。当前不接管 Agent loop、不扫描宿主会话文件、不访问模型隐藏推理，也不生成根因、责任或修复结论。

### 关联与快照

页面将附加操作称为「相同输入再次调用」。相同输入是观察依据，不能证明它有处理前一个错误的意图。

关联在新用户输入、助手结束、回合变化、中断或会话结束时停止；已知 `turn_id` 后缺少回合标识也停止。输入脱敏、截断、已知采集缺口不会被跨越。最多附加 20 次匹配调用，遇到下一次匹配错误即停止，同时将该错误保留为独立记录。当前规则为 `observed-errors-3`：旧来源缺少完整采集边界契约时仍保留、显示、导出，但不再自动附加后续调用；不改写旧来源或过去下载的文件。

一个概念示例：同一回合执行 `python read_config.py` 返回 `FileNotFoundError`，随后相同调用返回 `Loaded config.json`。记录能展示这两个观察，不能推断是谁创建了文件、为什么缺失或整个任务是否已经修好。

列表按来源序号从新到旧直接读取，每次扫描最多 500 个工具事件、返回最多 100 条命中。首次打开固定事件截止位置；加载更多沿同一快照继续，新事件需要刷新查看。某一页没有命中时仍可能有更旧事件，页面会保留继续扫描入口。读取不再依赖派生索引写入，因此索引未追上或数据库达到采集容量不会阻断已存记录的查看。

详情和 Markdown 导出绑定同一事件截止位置与规则版本。后续事件不改变已下载文件；来源序号和 SHA-256 用于核对保存副本，不证明现实中的内容一定正确。

## 本地数据、容量与费用

来源是经过字段选择、有限脱敏和可能截断的保存副本，不是完整原始宿主事件。适配器保留回合、调用、事件身份和候选状态字段，标记版本、未知字段数量及缺口；旧来源不会为了补齐字段而被重写。

单个字段通常保留至 32 Ki 字符量级；较长的返回字符串保留首尾并显示缺口。每个会话的普通采集预算为 10 MiB / 5,000 个事件；达到其中一个限制后，只允许当前检测器能识别的错误再使用最多 512 KiB / 128 个事件的有限余量。数据库还有约 256 MiB 的采集保护阈值。这些不是永不漏记的保证，也不是自动归档策略。

整条 Hook 输入超过 512 KiB 会在 JSON 解析前拒收，正文不保存，也不从截断前缀猜项目或会话。拒收和本地存储错误留下不含正文的诊断码；已知会话缺口停止关联，归属未知的拒收则在各会话后续来源中设保守边界，连续的新来源可重新关联。恢复后的连续性未知、诊断不可读也分别提示，不等同确认当前会话丢失事件。诊断持久化仍可能因目录不可写而失败；没有提示不等于持续正常送达。详见 [InputTooLarge 修复说明](docs/reports/NOTES-026-input-limit.md)。

默认采集、检测、页面和导出不调用额外模型，不主动上传或将记录塞回对话。它们消耗本机 CPU、磁盘和运行时间。让 Codex 主动阅读、分析记录仍会消耗当前会话用量。历史受控实验每次 Hook 约 0.56～0.76 秒，不是本轮性能或长期体验保证。

本地 HTTP 只监听 `127.0.0.1`，使用随机 token、Host/Origin 校验和 CSP；来源按不可信文本显示。有限脱敏不能保证移除所有敏感信息，分享前仍需检查。「记录本地保存」不等于 Codex 的模型请求也在本地运行。

## 运行目录、停止、备份与恢复

兼容标识仍为 `tas-notes`、`TAS_NOTES_STATE_DIR` 和 `TAS Notes` 数据目录；不能因为产品改名就批量替换。默认位置由 `%LOCALAPPDATA%/TAS Notes` 决定，Codex 的 MSIX 环境可能映射到包的 `LocalCache`。**先以状态页面显示的物理数据目录为准，不自动迁移现有记录。**

状态目录优先级：显式 `--state-dir` / 安装器 `-StateDir`，其次 `TAS_NOTES_STATE_DIR`，最后默认位置。桌面安装器将实际物理路径写入入口，应用代码副本的位置不会决定数据位置。页面显示当前服务版本、build 和数据目录；插件源码、安装副本及运行中的服务可能不同步。

以下命令中用实际 Python 和源码路径替换占位值。数据、备份和恢复目录放在任何 Git 仓库与已登记项目之外；备份文件必须不存在，恢复目录必须是已有父目录下的新目录。

```powershell
$notesPython = '<Python 的绝对路径>'
$notesCli = '<源码目录>\plugins\tas-notes\scripts\tas_notes.py'
$notesState = '<已确认的物理状态目录>'
& $notesPython $notesCli --state-dir $notesState status
& $notesPython $notesCli --state-dir $notesState open
& $notesPython $notesCli --state-dir $notesState stop
& $notesPython $notesCli --state-dir $notesState backup '<新的备份文件.sqlite3>'
& $notesPython $notesCli restore '<备份文件.sqlite3>' '<新的恢复状态目录>'
```

`stop` 只向身份和 token 匹配的本地服务发送鉴权停止请求。发现其他 build 正在运行时，打开入口会提示先处理版本冲突，不暗中多开服务。旧版没有停止接口时，不按 registry 中的 PID 强制结束它；需确认并关闭原服务后再打开。

备份使用 SQLite 在线快照，并检查数据库完整性、引用关系与记录计数，返回文件摘要。恢复保留来源、总结及人工版本，只写入新目录，所有项目默认停用；同时建立恢复连续性边界，防止尚未进入数据库的诊断丢失后出现跨恢复关联。恢复不会替换当前库，不复制运行时配置或启动服务；需显式指定新状态目录、重新配置运行时，并逐项目决定是否启用。同盘备份仍会受到磁盘损坏影响，独立副本由用户自行保管。

桌面入口安装支持 `install_shortcuts.ps1 -Python <路径> -StateDir <状态目录>`。安装器只复制代码、资源和版本元数据，不迁移数据库；CRLF/LF 差异不会被误判为不同构建。已有数据库优先按文件句柄定位物理目录，兼容 MSIX 文件级重定向。本机插件、桌面入口及服务版本与物理目录已核对，见 [NOTES-022 桌面验收](docs/reports/NOTES-022-desktop-acceptance.md)；[此前安装报告](docs/reports/NOTES-022-installation-acceptance.md)保留当时证据。
