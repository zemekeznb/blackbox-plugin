# 发布草稿测试

普通用户请按 [安装指南](INSTALL.md) 安装公开版本。本页仅供维护者验证尚未公开的 Release 草稿，不是另一种日常安装入口。

## 下载与核验

1. 在 GitHub 登录有权限查看草稿的维护者账号，打开仓库 Releases 中待测试的草稿。
2. 下载同一版本的候选 ZIP、`.zip.sha256` 和 `.release-manifest.json`，不要用 GitHub 自动生成的 Source code 归档代替。
3. 核对 ZIP 摘要、内外清单、版本和来源提交；按[开发与验证](DEVELOPMENT.md)运行候选校验。缺少附件或校验失败时停止，不改用旧版本代替。

草稿附件不能匿名下载。凭据只用于 GitHub 下载，不写入插件配置或测试报告。摘要用于核对文件一致性，不是独立的发布者签名。

## 安装与验收

- 按已校验载荷内的 `release/INSTALL-CODEX.md` 审阅安装范围。草稿使用本地已校验附件，不能执行只适用于公开版本的下载引导。
- 使用独立、稳定的安装源目录。已有安装先确认原物理数据目录并完成备份验证；访问失败时保留现场，不切换空库冒充升级成功。
- 使用已有 Python 与正式 Blackbox 插件；不安装 Probe，不修改系统 PATH、ACL 或沙箱。项目采集和 Hook 信任须分别取得明确授权。
- 分别核验安装版本、运行绑定、原生侧边栏、完全重启后的新会话，以及授权项目的真实记录。网页打开、独立 MCP 进程与模拟 Hook 不替代桌面验收。
- 记录版本、来源提交、测试条件和脱敏后的结果。测试通过不自动授权发布；确认发布时使用同一份已测试附件，不覆盖旧版本。
