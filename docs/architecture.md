# TAS Notes 首版设计

## 用户路径

为项目启用记录 → 正常使用 Codex → 自动保留可取得的过程 → 本地查看详细材料和草稿 → Owner 编辑与审阅 → 导出选中的版本 → 沿现有渠道共享。

## 数据分层

1. 原始来源：允许捕获的可见消息、工具操作与结果；不采集隐藏推理，不自动遍历其他项目会话。
2. 自动草稿：从已保存来源派生的经过；保存来源引用和覆盖范围。记录结束不等于用户验收。
3. 人工版本：Owner 编辑的文字和版本，自动捕获不会覆盖。
4. 导出版本：明确选择的静态 Markdown；不包含未审阅的新增材料，不自动发布。

第一切片按「项目绝对目录 + 宿主会话 ID」分组，不自动推断跨会话属于同一调查。事件按本机落盘顺序显示；内容哈希针对清理后的已存材料，不证明宿主真实性或外部实验正确性。用户验收情况由人工文字说明，目前没有自动推断验收状态的模型。

记录不以成功为前提。失败、中断、未知结果与后续否定必须可见。信息不能只因为来自 Hook 就升级成独立验证过的技术结论。

## 组件

Codex 插件（可用 Hook / Skill）→ 本地受限事件入口 → SQLite 事务与去重 → 草稿渲染 → 本地人工审阅 / 导出。

组件不依赖父目录 `tas` 包，不初始化旧数据库，不连接 TAS 远程服务。运行数据位于用户选择的本机状态目录，默认在仓库之外。测试使用独立临时目录。

旧 TAS 复用的是 Claim/Evidence 分离、Owner 责任、事务与幂等等经验；这次没有直接导入旧业务模块。首个本地切片不复制旧服务的 Port/Adapter 和中央授权分层，避免为未验证需求增加工程体积。`Store` 是明确的本地基础设施实现，不声称已经建立可替换的通用领域层。

## 接入验收

- 识别实际 Windows Codex 版本、插件配置及支持的 Hook 事件。
- 命令参数必须正确处理空格和中文路径，不将用户文本拼进 shell 命令。
- 未启用项目不采集。有稳定 ID 的事件重复投递不重复写入；无稳定 ID 时保留，声明可能重复。
- 不因记录失败阻断用户正常任务；失败要在诊断入口可见。
- 异常退出后已提交事务保留；尚未送达的事件不承诺恢复。
- 若当前宿主只提供有限事件，展示覆盖限制，不暗中退回全盘会话扫描。

## 验证与迭代

当前结果见 [接入证据](integration-evidence.md)；NOTES-002 完成受控本机真实接入验证，NOTES-004 完成本地诊断与阅读改进。下一入口 [NOTES-005](tasks/NOTES-005.md) 是用户选定项目后的真实使用。

诊断通过同一 Store 的读事务取得各项目计数及最后事件，通过受限读取取得运行配置和历史错误；不新增数据库表或后台进程。CLI 与鉴权后的 `/api/status` 共用逻辑。运行配置可识别不等于可执行，已落盘不等于持续健康，错误标记不自动推断为某项目当前故障。记录标题及中文概览仅由已保存材料确定性派生，不是模型总结，不回写来源或人工版本。

NOTES-001 先完成插件与本地最小流程、契约和恢复测试。真实宿主安装与自动触发独立记录；文档网页、CLI schema、合成测试各自只能证明其范围。之后再增加有来源约束的模型整理、跨会话关联和真实使用评估。
