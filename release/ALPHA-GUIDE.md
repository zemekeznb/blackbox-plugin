# Blackbox Plugin — Alpha 使用说明

Blackbox 面向 Windows 版 Codex 桌面端，为明确启用的项目保存宿主送达的本地事件，按项目和会话回看可识别的执行错误，并导出 Markdown 记录。安装与首次接入请从[安装指南](INSTALL.md)开始；本页说明日常使用、保存范围和当前限制。

## 使用前了解

- 需要 Windows 版 Codex 桌面端与宿主可调用的 Python 3.11+。Codex CLI 使用支持后续再补；最低 Codex 版本、干净电脑及 API Key 登录模式尚未完成专项验收。
- 项目采用 [MIT 许可证](../LICENSE)，仍处于 Alpha 试用阶段；第三方字体保留其[原有许可声明](../plugins/blackbox/assets/review.css)。
- 安装、启用项目、Hook 已信任与真实记录收到是不同状态。只有实际核验命令记录送达，才算完成该项目的接入。

## 保存范围与隐私

记录只针对明确启用的项目，且仅接收宿主确认的持久桌面会话。终端 CLI 会话（包括安装辅助终端）不采集；正常桌面会话未命名或已归档仍可接收。保存范围包含获授权的可见输入、回复、工具调用及返回，**不只错误**。页面展示可识别的异常及保守关联的后续操作，不推断根因、责任或修复成功。

数据默认留在本机，不自动上传、发送记录或调用额外模型，也不会自动启用其他项目。有限脱敏不能保证去除密码、密钥或业务内容。默认目录为 `%LOCALAPPDATA%\Blackbox`；Windows 打包应用可能映射目录，以状态输出的实际路径为准。旧版本数据和配置仍保留兼容。

宿主没有投递的事件无法补记，无法识别的错误可能漏记；“暂无异常”不表示没有失败。临时、内部或身份尚未确认的会话不保存正文。.45 升级后旧身份缓存需要重新核对，核对期间未确认的事件不会补回；已按新规则验证的桌面会话继续受暂时传输故障保护。升级不自动删除旧记录。

## 日常查看与导出

安装与初始化完成后，在 **Codex 桌面端侧边栏**找到并点击 **Blackbox**，即可打开记录页面。也可以在 Codex 桌面会话中发送“打开 Blackbox。”，让 Codex 协助打开。

继续在已接入项目的 Codex 桌面会话中工作，需要复盘时选择项目和会话，使用时间或类型筛选查找记录，再查看命令、返回与关联操作。

导出前检查完整 Markdown 预览及来源字段。导出保存的是固定范围快照，不会上传；分享前仍需自行检查敏感内容。

Codex 内 Blackbox 页面的“保存到下载文件夹”会将已预览并校验的内容写入 Windows 实际配置的下载目录，同名文件自动编号；本地浏览器阅读页使用浏览器下载。以成功结果中的完整路径为准，保存超时先检查目标目录，避免重复保存。

官方查询明确未关联的记录从日常导航隐藏，底层历史不会因此自动删除。这不表示记录已归档或一定来自子代理；临时名称查询失败也不作为删除依据。

## 接入项目

首次接入时，按 Blackbox 初始界面的引导，点击 **接入第一个项目**。后续接入其他项目时，点击页面左下角 **采集与隐私** → **使用与排查** → 展开 **如何接入新项目？**。

阅读保存范围，将对应入口提供的提示词复制并发送到**目标项目的 Codex 桌面会话**。Codex 会协助官方 Hook 信任审阅、启用该项目，并用无副作用的真实命令验证对应记录是否收到。每个新项目都需要明确接入，不能仅凭安装成功或项目已启用判定采集生效；需要重开时按提示继续验证。

## 停用、备份与恢复

在采集设置中停用指定项目，历史记录保留。关闭页面或停止阅读服务不会停用采集。清理记录前先确认范围；文档更新、普通安装或卸载不会自动删除历史。

可以在 Codex 中请求 `blackbox-review` 将数据备份到项目和 Git 仓库之外的新文件。备份仍可能包含敏感信息，不自动加密或上传；数据库快照不包括运行命令、服务令牌和阅读偏好。

恢复只写入新目录，所有项目默认停用，不覆盖当前数据库或自动恢复采集。需要重置体验时，先明确清理范围、停用项目、停止服务并验证备份。更新和卸载操作见[安装指南](INSTALL.md)。

## 当前限制与反馈

- 安装、准入规则的离线验证和用户实际桌面复测是独立证据；.45 复测交付后用户已反馈目前无问题，逐项 Hook 回执与完整步骤尚未独立核对，详见[当前进展](../docs/current-status.md)。
- 更新插件后，正在执行的长回合可能出现投递缺口。需要重开时，保存工作并完整退出 Codex，再继续验证真实记录；不会补造期间未收到的事件。
- 混合输出、静默失败和部分非 Bash/MCP 失败存在漏记边界；完整打印的诊断文本也可能误报。识别结果不能替代对实际执行情况的核查。

遇到问题时，向执行安装或接入的 Codex 会话提供版本、操作步骤和脱敏后的具体报错，区分“无法安装”“界面未打开”和“项目已启用但无回执”。不要直接上传完整数据库或凭据。

最新验证状态见[当前进展](../docs/current-status.md)；开发测试和构建方法见[开发与验证](../docs/DEVELOPMENT.md)。
